# Purpose

Rebuild reports, scorecards, matrices, research notes, and owner-review evidence.

# Ownership

This subtree owns durable rebuild evidence and decision records. Reports should make the next phase easier, not preserve chat history.

# Local Contracts

- Reports are evidence, not diary entries.
- Keep scorecards current and remove stale contradictions.
- Matrix documents should state stable source availability, missing-data policy, and proxy policy.
- Phase reports must include final decision, files changed, checks, no-live-change confirmation, warnings, and next phase when those details apply.
- Do not imply champion activation, production exposure, or live-ranking changes unless an owner-approved phase actually did that work.
- Keep historical validation backlog files out of packaging unless the owner explicitly asks to commit them.

# Work Guidance

Use concrete counts, command names, table names, job IDs, and warning text when they matter. Keep reports concise. Do not rewrite large docs just to change tone.

# Verification

Use cheap markdown/readback checks for doc-only edits. Do not run full tests for docs-only work unless a phase explicitly requires it.
